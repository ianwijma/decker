## Visibility is an owned lease, not a render side effect

Implement a main-owned visibility registry keyed by exact deck/profile/page/binding/generation plus refresh-definition identity. A binding is active while at least one eligible live surface holds a valid lease. Deduplicate React rerenders, repeated snapshots, multiple browser tabs/clients and multiple surfaces showing the same deck. A second client arriving during an existing visible epoch must not fire another initial refresh. Removing one of two clients must not stop the shared refresh. Do not share state between distinct decks that happen to use the same profile/binding.

Eligible surfaces:

- Hardware: the configured deck's current page on a device actually in ready state. Discovery/presence, native-driver-ready and permission/busy/open/I/O errors do not count. Hardware refresh continues when the editor is closed to tray. Disconnect/device worker exit immediately drops its leases. Navigation/configuration changes invalidate the old page. Do not let a delayed ready report for an older desired page activate the wrong bindings; use a stable applied-page/view epoch if needed. Dynamic label/image/status updates must not change the visibility epoch or recursively retrigger initial refresh. Keep native frame deduplication.
- Simulator: the active simulator deck page actually shown by the desktop Deck view. Leaving that route/page/deck, hiding/minimizing/closing the window, renderer crash/navigation or stale lease expiry removes it. Main validates the renderer sender/window and the committed selected deck/page; a claimed ID alone is insufficient. Editing a hardware/web deck preview must not count as its real hardware/foreground-browser surface. Treat focus changes separately from hiding so a visible app is not constantly restarted by ordinary focus transitions.
- Web: at least one authenticated paired, foreground browser displaying the authorized deck's current page/view. Pairing alone or WebStatus.clients.online is insufficient. Track per-socket current-view acknowledgement/visibility with bounded freshness; a stale view, hidden page, closed/dead socket, revoked pairing, server disable/restart or navigation removes its lease. Never trust a browser-supplied deck/binding/workflow authority; server derives deck from authentication and keys from the accepted current view. Keep origin/host checks, monotonic sequences, payload/rate limits, held-key reset and per-deck asset authorization.

Current web/client.ts closes its socket on document.hidden/pagehide, reconnects only when visible and uses a heartbeat; WebDeckServer currently reports online socket state but no foreground/page lease. Extend this protocol deliberately, including page acknowledgement after receiving a view and expiry after missing freshness. Existing view.version identifies the page/binding map, while appearance-only updates should not restart a lease. Main must validate worker incarnation/configuration before accepting reports. The current hardware Frame/status lacks an explicit applied page ID: add only the minimal tested metadata needed rather than assuming any cached ready flag proves the current page is displayed.

Use bounded lease counts/TTL, injected clocks and clear ownership on every teardown. Browser visibility reports are cooperative telemetry, not a guarantee against a malicious paired client; authorization and rate/concurrency bounds still constrain it. No new public execution/target IPC. Expiration and cancellation cannot wait behind a slow download or global document mutation queue. Main owns timers/work; React effects may report visibility, never directly run workflows.
